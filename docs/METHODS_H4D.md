# H4d: private v0.1 release protocol

Declared October 23, 2026, before export implementation. The user selected:
keep the current defaults, including Clearer; ship the twelve additional named
gradient routes as experimental alternatives. No PyPI publication, GitHub
release publication, repository-privacy change or downstream integration is
part of this work.

Keep all previous recipes, numerical sources, thresholds and evidence intact.
A separate release registry records immutable identifiers, recipe hashes,
family/background/count, default/legacy/experimental role and the scope of
appearance review. Release inclusion is distinct from a human-discrimination
certificate. Frozen reports retain their original approval/review flags.
Discovery reads this small registry without loading large audit resources.
Loading by immutable ID may cache immutable prepared objects. Nearby-count
advice uses only prepared passing uniform counts; unlisted counts are unknown.

The export/import bridge is versioned, data-only and hashed. Compact JSON
retains the exact source recipe and optional explicit uniform selection,
source orientation, category labels and exported colors. Large audit evidence
is omitted; import repeats established recipe/count validation and never trusts
supplied pass claims. Known shipped recipes use their frozen evidence, unknown
recipes need the existing independent audit, and `validate=False` is explicitly
unvalidated where evidence is unavailable. Positioned palettes retain their
exact source and positions. Naked discrete palettes require their source for
complete JSON files; hex/CSV remain available as color-table exports.

Text/CSV exports preserve exact hex colors and declared sample positions.
Positions are normalized sample locations, never inferred physical boundaries.
Continuous table sampling requires an explicit passing count. Discrete CSS
uses exact step colors. Continuous CSS explicitly requests encoded-sRGB
interpolation and uses adaptively refined odd-count stops, including endpoints
and the shared t=.5 center. Default maximum float Oklab approximation error is
.002, independently checked on at least 8193 normal positions and the same
nonaligned normal/CVD grids used by H4a. Quantized error is reported separately.
Failure at the stop cap is an error; no clipping or tolerance relaxation.
CSS evidence is a finite-grid approximation, not a new H1 approval or browser
rendering certificate. Labels must be unique and count-matched.

Acceptance: all registered IDs and old recipes still load offline; discovery
and export use no optional imports; exact JSON roundtrips cover every family,
both backgrounds, reversal, selected counts and positioned palettes. Reject
tampered hashes, schemas, nonfinite data, fabricated colors/selection claims,
duplicate labels and exhausted CSS tolerances. Exercise export colors and
signed centers through all three actual backends. Repeat all H0–H4c checks,
clean wheel/sdist installs, and Windows/Linux Python 3.10/3.12/3.14 CI.

Provide a short quick start, API guide, release notes and plotting examples.
Show the palette gallery directly in the README using ordinary images that
GitHub can display. Keep numerical checks and scientific limitations available
in the methods notes.

CSS interpolation contract:
[CSS Images 4 linear gradients](https://www.w3.org/TR/css-images-4/#linear-gradients)
and [CSS Color 4 interpolation](https://www.w3.org/TR/css-color-4/#interpolation-space).
